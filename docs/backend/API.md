# AddaApp API v1 — contract

Base URL: `{API}/api/v1` (dev: `http://localhost:3013`, Android emulator: `http://10.0.2.2:3013`).
All bodies are JSON. **Money is always integer paise** (`amountPaise`, `pricePaise`, `totalPaise` …; ₹1 = 100). Dates: ISO strings; date-only fields are `YYYY-MM-DD` (IST); billing periods are `YYYY-MM`.

## Conventions
- PATCH endpoints change only the fields sent (no create-time defaults are re-applied).
- Marketplace items in `/society/listings` and `/platform/listings` include `category:{name,icon}`.
- Rate limits per IP: sign-in/sign-up/password 20 per 15 min (`LOGIN_RATE_LIMIT`), token refresh 600 per 15 min, public forms 60 per hour (`PUBLIC_FORM_RATE_LIMIT`).
- Auth: `Authorization: Bearer <accessToken>`. Access tokens last 15 min. On `401` with `error.code` `TOKEN_EXPIRED`, call `POST /auth/refresh` once with the stored refresh token, replace BOTH tokens (rotation), retry. If refresh fails → sign out locally.
- Optional `X-Society-Id` header selects which of the caller's own societies to act in (only needed when a user has several). It never grants access.
- Errors: `{ "error": { "code": "STRING", "message": "Human readable", "details"?: any } }`. Show `message` to users. Notable codes: `VALIDATION_ERROR`(400), `UNAUTHORIZED`/`TOKEN_EXPIRED`/`TOKEN_INVALID`/`SESSION_INVALID`/`ACCOUNT_DISABLED`(401), `FORBIDDEN`, `MEMBERSHIP_PENDING`, `MEMBERSHIP_REQUIRED`, `SOCIETY_SUSPENDED`, `NO_PANEL_ACCESS`(403), `NOT_FOUND`(404), `CONFLICT`/`DUPLICATE`/`SLOT_TAKEN`/`ALREADY_VOTED`/`INVOICE_PAID`(409), `ACCOUNT_LOCKED`(423), `TOO_MANY_REQUESTS`(429, `details.retryAfterSeconds`), `OTP_UNAVAILABLE`/`PAYMENTS_UNAVAILABLE`(503).
- Paged lists: query `page`, `limit` (≤100), `sort` (e.g. `-createdAt`), `q`, `status` → `{ items: [], page, limit, total, pages }`.
- Media objects in responses: `{ _id, url, mimeType, originalName, size }` — `url` is directly loadable (signed for private files, expires ~6h; re-fetch the parent record to refresh).
- Populated refs come back as objects (`{ _id, name }`), otherwise as id strings.

## Listings (any signed-in user; no membership needed)
- Property: `GET /properties?listingType=sale|rent&propertyType=apartment|house|plot|commercial|room&city=&locality=&minPrice=&maxPrice=&bedrooms=&q=&sort=pricePaise|-pricePaise|-createdAt` (paged; item `{_id,listingType,propertyType,title,description,pricePaise,areaSqft,bedrooms,bathrooms,furnishing,amenities,locality,city,photos[],contactName,contactPhone,whatsappAvailable,availability,moderationStatus,postedBy,society:{name}?,mine}`); `GET /properties/mine`; `GET /properties/:id`; `POST /properties` **(KYC-approved vendors only: 403 `VENDOR_ONLY` / `KYC_REQUIRED`)** `{ listingType, propertyType, title, description?, pricePaise, areaSqft?, bedrooms?, bathrooms?, furnishing?: unfurnished|semi_furnished|furnished, amenities?, locality?, city, address?, photos?, contactName?, contactPhone, whatsappAvailable? }` → `moderationStatus: pending|approved` (platform rule; vendor listings have no society); `PATCH /properties/:id` (same fields + `availability: available|sold|rented|inactive`; content edits return to `pending`); `DELETE /properties/:id`; `POST /properties/:id/report` `{reason}`

- **Sponsored results**: on page 1, `GET /properties` and `GET /service-offers` put listings with a running boost first, flagged `sponsored: true` (max 5, never repeated below; `sponsoredCount` in the page). Boost location = `city` query, else the viewer's profile city, else all running boosts; the other browse filters still apply.
- **Service offers** (vendors list; members browse and book): `GET /service-offers/categories` (platform service categories + the caller's society ones); `GET /service-offers?categoryId=&city=&q=&mySociety=true` (approved + active only; `visibility: society` offers only to members of that society; item `{_id,title,description,category:{name,icon},priceType,pricePaise?,experienceYears?,serviceArea,city,availabilityNote,photos[],contactName,contactPhone,whatsappAvailable,visibility,status,society:{name}?,postedBy,mine,shop:{name,logoUrl},pricing,createdAt}`); `GET /service-offers/mine`; `GET /service-offers/:id` (404 if not visible to you); `POST /service-offers` **(KYC-approved vendors only)** `{ categoryId, title(5-140), description?, priceType: fixed|starting_from|per_hour|per_visit|on_quote, pricePaise (the VENDOR's price; required >0 unless on_quote; max ₹10,00,000), experienceYears?(0-60), serviceArea?, city, availabilityNote?(≤120), photos?(≤6, purpose service), contactName?, contactPhone, whatsappAvailable? }` — strict (unknown keys, incl. the old `visibility`, → 400) → 201 `moderationStatus: pending|approved` (platform rule); the service takes the vendor's shop location; max 10 live offers per person → 409 `OFFER_LIMIT`; `PATCH /service-offers/:id` (same fields + `status: active|paused`; content edits return to `pending`; status-only changes keep approval); `DELETE /service-offers/:id` (soft delete); `POST /service-offers/:id/report` `{reason}` (409 if already reported). Moderation decisions notify the provider with route `MyServices`.
- **Prices (per vendor).** Members see and pay the vendor's price; NIVASA's commission is **taken out of it** (shown only to the vendor) and the member discount is a share **of that commission**, paid by NIVASA: `commission = round(vendorPrice × commissionPercent/100)`, `memberPrice = vendorPrice`, `vendorEarnings = vendorPrice − commission`, `discount = round(commission × memberDiscountPercent/100)`. ₹1,000 at 20% → members pay ₹1,000 (₹900 with a 50% discount), vendor earns ₹800. Rates are live for services and snapshotted on bookings. **Members** get `pricePaise` = member price and `pricing:{ memberPricePaise, discountAvailable, discountPaise, payableWithDiscountPaise }` — never the vendor price or rates. **The owning vendor** gets `pricePaise` = own price and `pricing:{ vendorPricePaise, vendorEarningsPaise, commissionPercent, commissionPaise, memberPricePaise, memberDiscountPercent, discountPaise, payableWithDiscountPaise }` and `location:{lat,lng,label}|null`. "Price on request": all price fields null, `discountAvailable:false`.
- **Near me**: `GET /service-offers?lat=&lng=&radiusKm=&sort=nearest` (lat −90…90, lng −180…180, `radiusKm` 1–100, default 10; lat and lng together; `radiusKm`/`sort=nearest` need them; anything else invalid → 400 `VALIDATION_ERROR`). Same visibility/moderation/category/q filters; only services whose shop location is inside the radius (services without a location are left out), nearest first, each with `distanceKm` (haversine, 1 decimal); no sponsored rows; response adds `near:{lat,lng,radiusKm}`.
- **Service bookings (members)**: `POST /service-offers/:id/bookings` `{ preferredDate: YYYY-MM-DD (today … +90 days, India time), preferredTime?: HH:MM, address(5-300), note?, applyDiscount?: true }` — strict (an old `couponCode` → 400) → 201 booking priced from the vendor's CURRENT rates (never from the client); `applyDiscount` with no discount (vendor discount 0% or "price on request") → 409 `NO_DISCOUNT`; vendors → 403 `MEMBER_ONLY`; one open booking per service → 409 `BOOKING_EXISTS`. `GET /service-bookings?status=requested|accepted|declined|cancelled|completed|open` (paged, own); `POST /service-bookings/:id/cancel` `{note?}` (only requested/accepted, else 409).
  Booking item: `{ _id, status, offerTitle, priceType, pricePaise (member price), preferredDate, preferredTime, address, note, pricing:{memberPricePaise, listPricePaise (= member price), discountApplied, discountPaise, payablePaise, + vendor only: vendorPricePaise, commissionPercent, commissionPaise, memberDiscountPercent}, payment:{status: unpaid|paid, method: cash|null, amountPaise, paidAt, note, + vendor only when paid: cashPaise, grossPaise, commissionPaise, discountPaise, netToPlatformPaise, vendorEarningsPaise}, timeline:[{status,note,at}], offer:{_id,title,city,category,photo}, vendor:{name,phone,whatsappAvailable} (customer view) | customer:{name,phone} (vendor view), role, actions:[…], createdAt }`. Flow: requested → accepted|declined|cancelled; accepted → completed|cancelled; a completed booking can be marked paid once. Bookings made before per-vendor pricing keep their old numbers (old coupon fields are ignored).

## Vendor (`/vendor/*`, accountType vendor in the app — else 403 `VENDOR_ONLY`)
- `GET /vendor/profile` → masked KYC `{ businessName, businessType: individual|business, city, address, kycStatus, kycNote, submittedAt, reviewedAt, consentAt, pan: '••••••234F', aadhaar: 'XXXX XXXX 1234', bankAccountHolder, bankAccount: '••••••1234', bankIfsc, bankName, documents:{panPhoto,aadhaarFront,aadhaarBack: {_id,url(signed, 10 min),mimeType}|null}, shop:{ name|null, logo:{_id,url}|null, location:{lat,lng,label}|null }, pricing:{ commissionPercent, memberDiscountPercent }, kycAvailable }`
- **Shop settings**: `PUT /vendor/shop` (strict, at least one field) `{ shopName? (2-80), logoId? (own upload, purpose `vendor_logo`; `null` removes), location?: {lat,lng,label?} | null (clears) }` → same shape as `GET /vendor/profile`. A new/cleared location is copied to every service of the vendor (near-me search). Audited `vendor.shop_updated`. Services show `shop:{name (shop name, else business name), logoUrl}`.
- `PUT /vendor/kyc` (strict) `{ businessName, businessType?, city, address?, pan (ABCDE1234F), aadhaar (12 digits, Verhoeff-valid; spaces ok), bankAccountHolder, bankAccountNumber (9-18 digits), bankIfsc (SBIN0001234), bankName?, panPhoto, aadhaarFront, aadhaarBack (3 different own uploads, purpose kyc), consent: true }` → profile with `kycStatus: pending`. PAN / Aadhaar / account number are stored AES-256-GCM encrypted (`KYC_ENCRYPTION_KEY`) and never returned in full to the vendor. 409 `KYC_APPROVED` once approved; 503 `KYC_UNAVAILABLE` when the server has no key.

## Products & orders (skills/vendor-products)
All need a signed-in app user. Same pricing rules as services (members pay the listed price, commission comes out of the vendor share, member discount = share of it). Vendor order `yourEarningsPaise` = payable − (commission − discount).
- Categories: `GET /products/categories` → `{ items:[{_id,name,icon,description}] }` (active platform categories of kind `product`, managed in Master Admin → Categories).
- Browse (members): `GET /products?q=&categoryId=&city=&inStock=true&lat=&lng=&radiusKm=&page=&limit=&sort=pricePaise|-pricePaise|-createdAt` (approved + active only; near me like services: `distanceKm`, nearest first). Item (member view):
  `{ _id, title, description, unit, category:{_id,name,icon}, photos:[{_id,url}], stock, inStock, maxPerOrder, delivery, pickup, deliveryChargePaise, city, status, shop:{name,logoUrl}, mine:false, pricePaise (member unit price), pricing:{memberPricePaise, discountAvailable, discountPaise (per unit), payableWithDiscountPaise}, distanceKm? }` — never vendor price or rates.
- `GET /products/:id` (members: approved + active only, else 404; the owner sees own pending/rejected too).
- Vendor (KYC approved, else 403 `KYC_REQUIRED`; members 403 `VENDOR_ONLY`): `GET /products/mine`; `POST /products` (strict) `{ categoryId, title(2-140), description?(≤3000), photos?: [ids ≤6, own uploads purpose product], pricePaise (vendor price ≥100, whole paise), unit?(≤40), stock(0-100000), maxPerOrder?(1-100, default 10), delivery?(default true), pickup?(default false), deliveryChargePaise?(≥0), status?: active|paused }` (delivery or pickup required) → 201 owner view; `PATCH /products/:id` (any subset; title/description/unit/photos/category changes go back to `pending` when listings need approval; stock/price/status don't); `DELETE /products/:id`. Owner view adds `{ pricePaise (vendor price), moderationStatus, moderationNote, location, pricing:{vendorPricePaise, commissionPercent, commissionPaise, memberPricePaise, memberDiscountPercent, discountPaise} }`. 409 `PRODUCT_LIMIT` (200). Location = shop location.
- Report: `POST /products/:id/report` `{reason}`.
- **Place order** (members only, 403 `MEMBER_ONLY`): `POST /products/:id/orders` (strict) `{ quantity (1…maxPerOrder), fulfilment: delivery|pickup, address (required for delivery, 5-300), note?, applyDiscount?, paymentMethod: cod|online }` → 201 `{ order, checkout }`.
  Payable = memberUnit×qty − discountUnit×qty + deliveryCharge (delivery only). Stock is reserved at once (409 `OUT_OF_STOCK` "Only N left"). 409 `NO_DISCOUNT`; 400 `PHONE_REQUIRED`.
  `cod` → order `placed`, `checkout: null`. `online` → order `awaiting_payment` + `checkout` (see Online payments); 409 `VENDOR_PAYOUT_NOT_READY` when the shop has no active Cashfree account (offer COD); 503 `PAYMENTS_UNAVAILABLE` when the gateway is off. Unpaid online orders are cancelled after 30 min (stock restored).
- Member orders: `GET /product-orders?status=<status>|open`; `GET /product-orders/:id`; `POST /product-orders/:id/cancel` `{reason?}` (only `awaiting_payment|placed|confirmed`, else 409; online-paid → refund started); `POST /product-orders/:id/pay` → checkout (only `awaiting_payment`).
  Member order: `{ _id, orderNumber (NV0000123), product:{_id,title,unit,photoUrl}, quantity, fulfilment, address, note, shopName, pickupAddress (pickup only), paymentMethod, status, statusText, timeline:[{status,note,at}], cancelledBy: member|vendor|system|null, cancelReason, memberUnitPaise, memberTotalPaise, discountPaise, deliveryChargePaise, payablePaise, payment:{status: unpaid|paid|refund_pending|refunded, method: cash|online|null, amountPaise, paidAt, refundedAt}, actions: ['cancel'?, 'pay'?], createdAt }`.
  Status flow: `awaiting_payment → placed → confirmed → packed → shipped → out_for_delivery → delivered` (delivery) or `… packed → ready_for_pickup → delivered` (pickup); `cancelled` from awaiting_payment/placed/confirmed/packed.
- Vendor orders: `GET /vendor/orders?status=|open` (never shows `awaiting_payment`; `counts:{status:n}`); `GET /vendor/orders/:id`; `POST /vendor/orders/:id/status` `{ status: confirmed|packed|shipped|out_for_delivery|ready_for_pickup|delivered|cancelled, note? (required for cancelled) }` (409 `INVALID_TRANSITION`). COD orders are recorded as paid in cash at `delivered`. Vendor order = member order + `{ customer:{name,phone}, vendorUnitPaise, vendorTotalPaise, commissionPercent, commissionPaise, yourEarningsPaise (vendor total + delivery), settlement:{…same fields as service bookings}|null, nextStatuses:[…] }`.
- Earnings (`/vendor/earnings`, `/platform/earnings`) now include paid product orders: `totals` = services + products, plus `breakdown:{ services:{…}, products:{…} }` (same fields as totals). `items` stay service bookings.

## Online payments (Cashfree, skills/cashfree-payments)
`GET /public/config` → `payments:{ gatewayConfigured, provider: 'cashfree'|null, mode: 'sandbox'|'production'|null }`. Show a **"Test mode"** badge on every pay button/screen when `mode === 'sandbox'`.
- Checkout object (returned by every pay endpoint): `{ orderId (inv_|fac_|bkg_|ord_ + 24 hex), kind: invoice|facility|booking|order, ref, amountPaise, status: created|paid|expired|amount_mismatch, mode, paidAt, lastError, checkoutUrl (null unless created), returnUrl: 'addaapp://payment-result' }`.
- Pay endpoints: `POST /resident/invoices/:id/pay` (+ `paymentId, provider, currency, invoiceNumber, societyName`; 503 when the society hasn't enabled online collection), `POST /resident/bookings/:id/pay` (facility fee; booking `confirmed`, fee > 0, once — 409 `ALREADY_PAID`), `POST /service-bookings/:id/pay` (status `accepted` or `completed`, listed price — member booking `actions` includes `pay`; 409 `NO_FIXED_PRICE` / `VENDOR_PAYOUT_NOT_READY`; a paid booking cancelled by the member or declined/cancelled by the vendor is refunded in full, `payment.status: refund_pending → refunded`), `POST /product-orders/:id/pay`.
- App flow: `WebBrowser.openAuthSessionAsync(checkoutUrl, 'addaapp://payment-result')` → then **always** `POST /payments/checkout/:orderId/refresh` and show the returned `status` (`paid` → success; `created` + `lastError` → failed, can retry; `created` → "still confirming", retry refresh). `GET /payments/checkout/:orderId` = status without asking Cashfree. Only the payer can read it (else 404).
- Server pages (HTML, not JSON): `GET /api/v1/pay/checkout/:orderId?t=…` (opens Cashfree), `GET /api/v1/pay/return?order_id=…` (Cashfree return_url; redirects to `addaapp://payment-result?order_id=…&status=paid|pending|failed|expired`).
- Webhook: `POST /api/v1/payments/webhook/cashfree` (signature `x-webhook-signature` + `x-webhook-timestamp`; payment + refund events).
- Facility booking items now carry `payment:{ status: unpaid|paid|refund_pending|refunded, amountPaise, paidAt, refundedAt }`. A member can't cancel a paid booking (409 `PAID_BOOKING`); staff cancel refunds it.
- Service booking `payment.method` may be `online` (settled like cash: same commission/discount/net/vendor fields).
- Vendor payout account: `GET /vendor/profile` → `payout:{ status: not_created|pending|active|failed|blocked, cfVendorId, providerStatus, message, updatedAt, ready, available }`; `POST /vendor/payout/refresh` → payout (refreshes an existing account's status). Master Admin: `GET /platform/vendors/:id` → `payout`, `counts.products`, `counts.orders`; `POST /platform/vendors/:id/payout` (`vendors.manage`) → creates the Cashfree Easy Split vendor from the approved KYC or refreshes its status → payout. Created automatically on KYC approval. Needs the vendor's email.
- Master Admin: `GET /platform/product-orders?vendorId=&status=&payment=` (`orders.view`) → paged platform orders (member + vendor fields + `vendor:{_id,name}`) + `totals` (settlement of paid orders); `POST /platform/product-orders/:id/refund-retry` (`vendors.manage`) for a `refund_pending` online order. Listings moderation supports `kind=product` (`GET /platform/listings?kind=product`, `POST /platform/listings/product/:id/moderate`). Categories accept `kind: product`.
- Society payments (`PATCH /platform/societies/:id/payments`): `settlementMode` adds `cashfree_split` (`linkedAccountId` = the society's Cashfree vendor id, money goes to the society's bank) and `platform_collect` (collected in NIVASA's Cashfree account, settled outside the app).
- New platform permission area: `orders` (view only) — "Product orders".
- Notification routes added: `MyOrders`(id=order), `VendorOrders`(id=order), `MyProducts`; type `order`.

## Master Admin: add vendors + KYC on their behalf (skills/admin-vendor-onboarding)
All need `vendors.manage` (owner, or a sub-admin who has it); else 403 `PERMISSION_DENIED`.
- Upload KYC documents / shop logo before the vendor exists: `POST /platform/vendors/uploads` (multipart `file`, `purpose: kyc|vendor_logo`) → 201 `{ _id, url (kyc: signed 10 min), mimeType, size, purpose }`. Owner = the admin until the vendor is created, then moved to the vendor (kyc stays private).
- **Add vendor**: `POST /platform/vendors` (strict) `{ name(2-120), phone (10-digit Indian mobile), email, password (≥10, strength rules), shopName?(2-80), logoId? (own vendor_logo upload), location?: {lat,lng,label?}, commissionPercent?(0-100, ≤2 dp), memberDiscountPercent?, kyc?: KycDetails }` → 201 `{ _id, name, phone (masked), email, profile (masked KYC view), pricing, payout, passwordLoginEnabled }`. 409 `ACCOUNT_EXISTS` (phone) / `EMAIL_EXISTS`; 400 on any invalid field/document (nothing is created). The vendor signs in to the app with that mobile + password ("Vendor"). Audited `platform.vendor_created` (actor = the admin / sub-admin).
- `KycDetails` = `{ businessName, businessType: individual|business, city, address?, pan, aadhaar (Verhoeff), bankAccountHolder, bankAccountNumber (9-18 digits), bankIfsc, bankName?, panPhoto, aadhaarFront, aadhaarBack (3 different kyc uploads by this admin, or the vendor's existing ones), vendorConsent: true (admin confirms the vendor agreed), approve?: boolean }`. Stored encrypted exactly like the vendor's own KYC. `approve: true` → `kycStatus: approved` at once (reviewedBy = the admin) and the Cashfree Easy Split payout account is created (when Cashfree is configured); else `pending` for review.
- **Edit KYC details** of an existing vendor: `PUT /platform/vendors/:id/kyc-details` `KycDetails` → `{ profile, payout }`. 409 `KYC_APPROVED` when already approved (reject first). Audited `platform.vendor_kyc_entered` / `platform.vendor_kyc_entered_approved`.
- `GET /platform/vendors` rows add `addedBy:{_id,name,role}|null`; `GET /platform/vendors/:id` adds `addedBy`, `kycEnteredBy`.
- **Sub-admin activity** (owner only): `GET /platform/subadmins/:id/activity?action=&page=&limit=` → `{ subAdmin:{_id,name,email}, counts:{vendorsAdded, kycEntered, total}, items:[audit entries {action, targetType, targetId, summary, changes, society, createdAt}], page, limit, total, pages }`. `GET /platform/audit-logs?actorId=` filters any audit list by who did it.
